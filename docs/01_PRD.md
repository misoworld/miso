# 프렙 카페 운영관리 웹 프로그램 PRD

- 문서 상태: MVP 초안
- 작성일: 2026-10-12
- 자료 기준일: 2026-09-18 마감
- 결정 상태: 자료에서 확인된 사실만 반영했으며, 제품 정책은 별도 표시함

## 1. 자료를 먼저 읽고 확인한 내용

### 1.1 짧은 요약

자료에는 메뉴·레시피·재료·가격, 일자별 판매, 입고·폐기·실사, 월 비용 계획과 일자별 비용 기록이 들어 있다. 판매 입력에서 메뉴 수익성, 손익, 재료 잔량으로 이어지는 MVP를 만들 수 있는 수준이다.

다만 메뉴 수익에 임차료·인건비까지 나눠 넣을지, 미래 손익을 어떤 기준으로 예상할지, 며칠치 재고를 주문 기준으로 삼을지는 자료에 정해져 있지 않다. 이 세 가지는 제품 결정이 필요하다.

### 1.2 확인된 기록

| 기록 | 건수 | 확인된 내용 |
|---|---:|---|
| 공급사 | 3 | 공급사 ID와 이름 |
| 재료 | 11 | 단위, 구매용량, 최초 가격, 납기 영업일, 안전재고 영업일, 공급사 |
| 메뉴 | 8 | 메뉴명, 판매 기준가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개당 재료 사용량, 포장 판매에만 쓰는 포장재 구분 |
| 재료 가격 이력 | 33 | 적용 시작일별 구매가격과 구매용량 |
| 영업 달력 | 457 | 2025-07-01부터 2026-09-30까지 영업·마감 여부, 날씨, 메모 |
| 판매 기록 | 6,112 | 2025-07-01부터 2026-09-18까지 일자·메뉴·채널별 수량, 할인, 순매출, 수수료, 당시 원가 |
| 초기 재고 | 11 | 2025-07-01 영업 시작 전 재료별 수량 |
| 재고 기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 |
| 월 비용 계획 | 120 | 월별 8개 비용 항목의 계획 금액 |
| 비용 기록 | 3,560 | 월 비용을 날짜별로 나눈 기록 |
| 자료 정보 | 10 | 매장명, 출처, 통화, 기록 기간 등 |

엑셀과 JSON은 같은 기록을 표현한 두 형식이다. 엑셀에는 안내 시트를 포함해 13개 시트가 있으며 계산식은 들어 있지 않다. JSON의 `settings`는 비어 있다. 판매 ID·재고 기록 ID·비용 ID의 중복과 주요 연결 ID의 끊김은 확인되지 않았다.

### 1.3 기획 시 주의할 점

1. 엑셀과 JSON을 모두 가져오면 같은 기록이 두 번 집계된다. 최초 적재와 복원 시 중복 방지가 필요하다.
2. 판매 기록은 주문 한 건이 아니라 일자·메뉴·판매채널별 합계다. 주문 건수, 객단가, 함께 구매한 메뉴 분석에는 쓸 수 없다.
3. 2026-09-19부터 2026-09-30까지는 달력만 있고 마감되지 않았다. 이 기간을 판매 0으로 처리하면 안 된다.
4. 빈칸은 해당 없음 또는 미입력이고 숫자 0과 다르다. 가져오기와 수정 시 두 상태를 보존해야 한다.
5. 금액은 원 단위이며 부가세 제외다. 재료는 g·ml·개가 섞여 있고, 구매가격은 한 포장 전체 가격이다.
6. 월 비용 계획과 일자별 비용 기록은 같은 비용을 두 방식으로 표현한다. 둘을 합산하면 비용이 이중 계산된다.
7. 과거 판매에는 당시의 개당 식재료·포장 원가와 결제수수료가 남아 있다. 과거 실적은 이 확정 기록을 보존해야 한다.
8. 실제로 센 재고는 실사 기록이 있는 일부 시점·재료에만 존재한다. 계산상 재고와 실제 재고를 같은 값처럼 보여주면 안 된다.
9. 2025년과 2026년의 연간 자료는 모두 일부 기간이다. 전체 연도처럼 비교하지 말고 포함 기간을 알려야 한다.
10. 수익성 분류, 미래 전망, 공통비용 배분, 재고 처리 정책은 아직 합의되지 않았다.

## 2. 제품 개요

### 2.1 해결할 문제

카페 운영 기록이 여러 표에 나뉘어 있어 판매를 입력한 뒤 어떤 메뉴가 이익에 기여하는지, 선택한 기간의 매출과 비용이 어떠한지, 어떤 재료가 부족한지 한 흐름으로 확인하기 어렵다.

### 2.2 제품 목표

운영자가 판매·비용·재고 변동을 기록하면 같은 자료를 바탕으로 메뉴 수익성, 기간 실적과 예상 손익, 재료 잔량과 발주 참고량을 확인할 수 있게 한다.

핵심 사용 흐름은 다음과 같다.

> 판매 기록 입력 → 메뉴별 수익성 확인 → 선택 기간 손익 확인 → 재료 잔량과 부족 재료 확인

### 2.3 1차 대상 사용자

- 제안: 프렙 카페 한 매장을 직접 관리하는 운영자 1명
- 상태: 4시간 MVP 범위를 위한 제안이며 확정되지 않음

### 2.4 성공 기준

- 운영자가 위 핵심 흐름을 한 번에 완료할 수 있다.
- 기록을 수정하거나 삭제하면 관련 실적과 재고 결과도 일관되게 갱신된다.
- 마감 전 날짜, 빈칸, 중복 자료 때문에 실적이 잘못 부풀거나 줄지 않는다.
- 백업 후 복원해도 주요 기록 수와 내용이 보존된다.
- 결과가 실제 실적, 예상값, 실제로 센 재고, 계산상 재고 중 무엇인지 구분된다.

## 3. MVP 범위

### 3.1 1차 구현할 핵심 기능

| 영역 | 요구사항 | 우선순위 |
|---|---|---|
| 기초 자료 | 제공된 매장 자료의 메뉴·재료·레시피·가격·영업일 정보를 사용할 수 있다. | 필수 |
| 판매 기록 | 판매 기록을 직접 추가·조회·수정·삭제할 수 있다. | 필수 |
| 판매 엑셀 | 정해진 판매 기록 양식을 내려받고 작성한 엑셀을 가져올 수 있다. | 필수 |
| 비용 기록 | 비용 기록을 직접 추가·조회·수정·삭제할 수 있다. | 필수 |
| 비용 엑셀 | 정해진 비용 기록 양식을 내려받고 작성한 엑셀을 가져올 수 있다. | 필수 |
| 재고 기록 | 재료 입고, 폐기, 실제 재고 확인 결과를 기록하고 잘못된 기록을 바로잡을 수 있다. | 필수 |
| 메뉴 수익성 | 선택 기간의 메뉴별 판매 실적과 수익성 판단값을 확인할 수 있다. 수익의 범위는 결정 1에서 확정한다. | 필수 |
| 기간 손익 | 실제 매출과 비용, 손익을 확인하고 예상값과 구분해 볼 수 있다. 예상 기준은 결정 2에서 확정한다. | 필수 |
| 기간 조회 | 일·주·월·분기·반기·연간 기준으로 기록과 결과를 조회할 수 있다. | 필수 |
| 재료 잔량 | 초기 재고, 판매에 따른 사용, 입고·폐기·실사 기록을 반영한 재료 상태를 확인할 수 있다. | 필수 |
| 발주 참고 | 부족 가능성이 있는 재료와 참고할 발주량을 확인할 수 있다. 판단 기준은 결정 3에서 확정한다. | 필수 |
| 저장 | 입력·수정한 기록이 다시 열었을 때 유지된다. | 필수 |
| 백업·복원 | 전체 기록을 백업하고 같은 프로그램에 복원할 수 있다. | 필수 |
| 자료 보호 | 잘못된 날짜·ID·단위·필수값과 중복 가능성을 알려 잘못된 집계를 막는다. | 필수 |

### 3.2 MVP에서 읽기 전용으로 둘 기초 정보

4시간 안에는 공급사, 재료 기본 정보, 메뉴, 레시피, 재료 가격 이력의 관리 기능을 넓히지 않는다. 제공 자료를 기준으로 조회하고 계산에 활용한다. 이 정보의 추가·수정·삭제는 2차 범위로 둔다.

### 3.3 4시간 MVP의 완료 수준

MVP는 실제 운영 전 검증용 작동 시제품을 목표로 한다. 한 매장과 한 명의 사용자가 제공된 자료를 이용해 핵심 흐름을 검증하는 수준이다. 보안·동시 사용·외부 서비스 연결까지 갖춘 운영용 제품은 목표에 포함하지 않는다.

| 단계 | 시간 | 완료 목표 |
|---|---:|---|
| 기획 정리 | 25분 | 자료 연결 관계와 미정 정책 확인 |
| 화면 흐름 설계 | 25분 | 핵심 흐름과 필요한 입력·결과 범위 확정 |
| 개발 | 120분 | 필수 기록, 조회, 가져오기, 분석, 저장 흐름 구현 |
| 검사 | 35분 | 핵심 흐름, 기간 경계, 중복·빈칸, 백업·복원 점검 |
| 배포·인계 | 15분 | 실행 가능한 시제품 전달과 제한사항 정리 |
| 예비 시간 | 20분 | 자료 예외나 수정 사항 대응 |

정책 결정이 늦어지거나 자료 오류가 발견되면 구현 시간에서 차감된다. 따라서 계산 기준을 복잡하게 확장하지 않고 제공 자료의 구조를 유지한다.

## 4. 2차 구현할 확장 기능

- 메뉴·레시피·재료·공급사·가격 이력의 추가·수정·삭제
- 여러 매장, 여러 사용자, 로그인과 권한 관리
- POS·회계·결제·공급사 시스템 연결
- 발주서 작성, 발주 상태와 입고 예정 관리
- 재고 부족 알림, 폐기 증가 알림, 마감 누락 알림
- 여러 예상 시나리오 비교와 계획 대비 차이 분석
- 메뉴별 공통비용 배분과 상세 수익성 분석
- 주문 단위 분석, 객단가, 함께 팔린 메뉴 분석
- 변경 이력과 승인 절차
- 모바일 최적화, 인쇄·보고서 내보내기, 고급 시각화

## 5. 데이터 사용 원칙

### 5.1 확인된 원칙

- 메뉴·재료·공급사·기록 ID를 자료 간 연결 기준으로 사용한다.
- 과거 판매의 당시 단가·할인·순매출·수수료·원가 기록은 보존한다.
- 포장 전용 재료는 포장 판매에만 관련된다.
- 마감되지 않은 날짜는 판매가 없는 확정 실적으로 간주하지 않는다.
- 비용 계획과 비용 기록의 용도를 구분해 이중 집계를 막는다.
- 단위가 다른 재료 수량을 하나의 수량으로 합치지 않는다.
- 가져오기 전 원본을 보존하고, 문제가 있는 행은 사용자가 알 수 있어야 한다.

### 5.2 아직 정하지 않은 원칙

- 메뉴 수익성에 포함할 비용 범위
- 예상 손익의 기준 기간과 예상 방식
- 부족 재료와 발주 참고량의 판단 기준
- 주의 시작일, 분기·반기·연간의 기간 정의
- 같은 ID를 다시 가져왔을 때 건너뛸지, 덮어쓸지, 사용자에게 선택받을지
- 저장 위치와 배포 방식
- 실제 재고 입력이 계산상 재고를 대체하는지, 차이 조정 기록을 남기는지

## 6. 주요 요구사항별 완료 조건

### 6.1 판매와 메뉴 수익성

- 제공된 판매 기록을 기간·메뉴·채널 기준으로 구분해 사용할 수 있다.
- 새 판매 기록을 저장한 뒤 해당 메뉴의 기간 실적에서 확인할 수 있다.
- 판매 기록 수정·삭제가 관련 결과에 중복 없이 반영된다.
- 과거 원가 확정값이 현재 재료 가격으로 임의 변경되지 않는다.

### 6.2 손익과 예상값

- 실제 실적과 예상값이 섞이지 않고 구분된다.
- 선택 기간이 일부 기간이면 그 사실을 알 수 있다.
- 마감되지 않은 날짜를 실제 매출 0으로 포함하지 않는다.
- 비용 계획과 비용 기록이 같은 결과에 중복 반영되지 않는다.

### 6.3 재고와 발주 참고

- 입고·폐기·실사 기록을 재료별로 확인할 수 있다.
- 실제로 센 수량과 기록으로 계산한 수량을 구분한다.
- 부족 판단에 사용한 기준이 결과와 함께 설명된다.
- 발주 참고량은 확정 발주가 아니라 운영자 판단을 돕는 값임을 알린다.

### 6.4 엑셀 가져오기

- 판매용과 비용용 양식을 각각 내려받을 수 있다.
- 양식의 열 이름, 날짜, ID, 숫자, 필수값 문제를 확인할 수 있다.
- 잘못된 파일을 가져와도 기존 기록이 손상되지 않는다.
- 같은 자료를 반복해서 가져올 때의 처리는 결정된 중복 정책을 따른다.

### 6.5 저장·백업·복원

- 저장 후 다시 열어도 입력 기록이 유지된다.
- 전체 기록을 한 번에 백업할 수 있다.
- 백업 파일을 복원하면 판매·비용·재고 기록과 기초 자료가 함께 돌아온다.
- 복원 실패 시 기존 자료가 손상되지 않는다.

## 7. MVP에서 제외하는 사항

- 결제, 실제 발주 전송, 세금 신고, 회계 전표 생성
- 부가세 포함 금액으로의 변환
- 여러 사용자의 동시 편집과 권한 관리
- 운영 수준의 보안·감사·장애 복구 체계
- 주문 건수와 고객 단위 분석
- 합의되지 않은 공통비용 배분이나 예상 방법의 임의 적용
- 화면의 최종 디자인 규칙, 기술 구성, 세부 계산식

## 8. 검사 항목

- 제공 자료의 기록 수와 주요 ID 연결이 유지되는지 확인한다.
- 엑셀과 JSON을 연이어 넣어도 같은 자료가 이중 집계되지 않는지 확인한다.
- 2026-09-18과 2026-09-19 경계에서 마감 실적과 미마감 달력이 구분되는지 확인한다.
- 빈칸과 0이 서로 바뀌지 않는지 확인한다.
- 매장 판매와 포장 판매의 재료 사용 구분이 유지되는지 확인한다.
- 판매·비용·재고 기록을 각각 추가·수정·삭제한 뒤 관련 결과를 확인한다.
- 일·주·월·분기·반기·연간 조회에서 포함 기간이 올바르게 안내되는지 확인한다.
- 백업 전후의 기초 자료와 판매·비용·재고 기록이 일치하는지 확인한다.

### 결정 1. 메뉴 수익성의 기준 — 답변 대기

쉬운 예시: 아메리카노 한 잔을 팔았을 때 그 판매 때문에 바로 생긴 원두·포장·결제 비용까지만 고려할지, 임차료와 인건비의 일부까지 메뉴에 나눠 넣을지를 정해야 한다.

- 선택 A: 판매에 직접 따라오는 비용까지만 반영
  - 장점: 현재 자료의 당시 원가와 수수료를 그대로 활용할 수 있고 이해하기 쉽다.
  - 한계: 임차료와 인건비를 포함한 최종 순이익은 아니다.
- 선택 B: 임차료·인건비 등 공통비용까지 메뉴별로 나눠 반영
  - 장점: 메뉴별 최종 이익에 가까운 값을 볼 수 있다.
  - 한계: 어떤 기준으로 비용을 나눌지 추가 결정이 필요하고 결과가 기준에 따라 크게 달라진다.
- 선택 C: A와 B를 모두 제공
  - 장점: 운영 판단과 최종 이익 관점을 함께 볼 수 있다.
  - 한계: 4시간 MVP에는 범위가 크고, 공통비용 배분 결정이 선행되어야 한다.

추천은 **선택 A**다. 판매 입력에서 메뉴 수익성으로 바로 이어지고, 제공 자료의 확정 원가 기록을 활용할 수 있어 4시간 MVP의 핵심 흐름을 가장 안정적으로 검증할 수 있다. 공통비용을 포함한 메뉴별 수익은 2차 기능으로 확장할 수 있다.
